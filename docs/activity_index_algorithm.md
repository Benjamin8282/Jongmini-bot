# 활동지수 노이즈 감소 파이프라인

게임 경매장 거래량 데이터에서 **실제 유저 활동 추세**만 추출하기 위한 통계 파이프라인 설명서.

---

## 왜 필요한가?

경매장 거래량을 단순히 합산하면 다음 노이즈가 섞인다:

| 노이즈 종류 | 예시 | 특징 |
|---|---|---|
| **이벤트 스파이크** | 강화 확률 이벤트 → 장사꾼이 재고 방출 | 1~2일 짧은 급등 |
| **요일 주기성** | 주말에 접속자 많음 → 거래량 자연 증가 | 7일 주기 반복 |
| **시즌 업데이트** | 신규 레이드 → 소비재 수급 구조 변화 | 기준선 자체가 영구적으로 이동 |
| **개별 아이템 특이성** | 특정 아이템만 패치로 수요 급변 | 바스켓 내 일부 아이템에만 영향 |

이걸 그냥 두면 "활동지수 120% → 유저 폭증!" 이라고 나와도 실제론 강화 이벤트 때문에 거래량만 늘어난 거일 수 있다.

---

## 파이프라인 구조

```
원본 거래량
    │
    ▼
[Phase A] Hampel 필터 ─── 이벤트성 스파이크 제거
    │
    ▼
[Phase B] STL 분해 ────── 요일 주기성 제거
    │
    ▼
[Phase D] PELT 변화점 ─── 시즌 업데이트 체제 전환 감지
    │
    ▼
체제별 정규화 (30일 이동평균 대비 %)
    │
    ▼
일별 중앙값 = 활동지수
    │
    ▼
[Phase C] MAD 이상치 ─── 잔여 이상치 플래그 (표시용)
```

---

## Phase A: Hampel 필터

### 무슨 알고리즘인가

이동 중앙값(moving median) 기반 스파이크 감지기.

각 데이터 포인트를 주변 7일 윈도우의 **중앙값**과 비교해서, 정상 범위(MAD × 3배)를 벗어나면 "스파이크"로 판정하고 로컬 중앙값으로 **교체**한다.

### 왜 이동평균이 아닌 중앙값인가

이동평균은 극단값에 끌려간다.
예를 들어 7일 중 하루 거래량이 10배 뛰면, 이동평균 자체가 높아져서 "이건 정상 범위야"라고 판단할 수 있다.
중앙값은 데이터를 크기순으로 나열한 가운데 값이라, 극단값 하나가 있어도 흔들리지 않는다.

### 파라미터

| 파라미터 | 값 | 의미 |
|---|---|---|
| window | 7 | 앞뒤 3일씩 총 7일 윈도우 |
| threshold | 3.0 | MAD의 3배 이상 벗어나면 스파이크 |

### MAD란?

**Median Absolute Deviation** (중앙절대편차):

```
MAD = median(|각 값 - 중앙값|)
```

정규분포에서 MAD × 1.4826 ≈ 표준편차(σ)이므로, MAD × 3 × 1.4826 ≈ 4.4σ에 해당. 꽤 보수적인 기준이다.

### 예시

```
날짜:    3/1  3/2  3/3  3/4  3/5  3/6  3/7
거래량:  100  105  98   102  850  103  99
                              ↑ 강화 이벤트 스파이크

중앙값 = 102
MAD = median(|100-102|, |105-102|, ...) ≈ 3
임계값 = 3 × 1.4826 × 3 ≈ 13.3

850 - 102 = 748 >> 13.3 → 스파이크 판정!
850 → 102 (중앙값)로 교체
```

## Phase B: STL 분해 (Seasonal-Trend Decomposition using LOESS)

### 무슨 알고리즘인가

시계열을 세 가지 성분으로 분해:

```
원본 = Trend(추세) + Seasonal(주기) + Residual(잔차)
```

- **Trend**: 장기적 상승/하락 흐름
- **Seasonal**: 반복되는 패턴 (여기서는 7일 = 요일 효과)
- **Residual**: 위 둘로 설명 안 되는 나머지 (= 비정상적 변동)

### 왜 쓰는가

주말에 접속자가 많아서 거래량이 자연적으로 올라가는 건 "유저가 활발해짐"이 아니라 그냥 요일 효과다.
이걸 안 빼면 매주 금토일마다 활동지수가 올라갔다 내려갔다 하는 톱니 모양이 나온다.

### LOESS란?

**LO**cally **E**stimated **S**catterplot **S**moothing.
각 점 주변의 데이터에 가중치를 줘서 부드러운 곡선을 피팅하는 방법.
전체 데이터에 하나의 곡선을 피팅하는 게 아니라, 각 지점마다 "근처 데이터만 보고" 곡선을 그린다.

### 파라미터

| 파라미터 | 값 | 의미 |
|---|---|---|
| period | 7 | 주기 = 7일 (요일 효과) |
| robust | True | 이상치에 덜 민감하게 피팅 |

### 결과

```
사용하는 성분 = Trend + Residual
버리는 성분 = Seasonal (요일 효과)
```

Trend(장기 추세)와 Residual(설명 안 되는 변동)만 남겨서, 요일 패턴 없는 "순수한 거래량 추세"를 얻는다.

## Phase D: PELT 변화점 탐지

### 무슨 알고리즘인가

**Pruned Exact Linear Time** - 시계열에서 통계적 성질이 바뀌는 "변화점(change point)"을 자동으로 찾는 알고리즘.

대형 업데이트로 아이템 수급 구조가 바뀌면, 거래량 100개가 정상이던 시기에서 거래량 300개가 정상인 시기로 넘어간다. 이게 **체제 전환(regime shift)**.

### 왜 필요한가

단순히 30일 이동평균으로 정규화하면, 업데이트 직후 30일 동안은 "이전 체제의 낮은 평균"이 기준이 되어 활동지수가 뻥튀기된다.

변화점을 찾아서 **각 체제 내에서만** 이동평균을 계산하면 이 문제가 해결된다.

### 작동 원리

1. 데이터를 N개 구간으로 나눈다고 가정
2. 각 구간 내의 분산(변동성)을 계산
3. "구간을 이렇게 나누면 구간 내 분산의 총합이 최소가 되는" 분할을 찾는다
4. penalty 값으로 "구간을 너무 많이 나누면 벌점"을 부여 → 과적합 방지

### 파라미터

| 파라미터 | 값 | 의미 |
|---|---|---|
| model | rbf | 커널: Radial Basis Function (가우시안) |
| min_size | 14 | 한 체제 최소 14일 (2주) |
| penalty | 5.0 | 변화점 추가 시 벌점 (클수록 보수적) |

### 예시

```
     체제 1              체제 2
  (시즌 전)            (시즌 후)
  거래량 ~100          거래량 ~300
                  ↑
              변화점 감지!

체제 1에서 100% = 체제 1 내 30일 평균
체제 2에서 100% = 체제 2 내 30일 평균
→ 업데이트 전후 기준선이 각각 독립적
```

### 체제별 정규화

변화점을 찾은 뒤 데이터를 구간으로 나누고, **각 구간 내에서** 30일 이동평균 대비 비율(%)로 변환.

```
정규화된 값 = (실제 거래량 / 해당 구간의 30일 이동평균) × 100%
```

100% = 해당 체제에서의 평균 수준이므로, 체제가 바뀌어도 지수가 자연스럽게 이어진다.

## Phase C: MAD 이상치 감지

### Hampel이랑 뭐가 다른가?

- **Hampel (Phase A)**: 원본 거래량에서 스파이크를 **교체**한다. 노이즈를 **제거하는** 단계.
- **MAD (Phase C)**: 정규화된 최종 결과에서 이상치를 **감지만** 한다. 차트에 마커로 **표시하는** 용도.

### 왜 2σ 대신 MAD인가

일반적인 "평균 ± 2σ" 방식의 문제:

```
데이터: [100, 100, 100, 100, 100, 100, 900]

평균 = 214
σ = 285
2σ 범위 = 214 ± 570 = [-356, 784]

→ 900이 범위 밖이긴 하지만, σ가 900 때문에 부풀려져서
  실제 이상치를 잡기 어려움 (마스킹 효과)
```

MAD 방식:
```
중앙값 = 100
MAD = median(|100-100|, ..., |900-100|) = 0
→ 극단값이 MAD를 부풀리지 못함
→ 더 정확한 이상치 감지
```

(실제로 MAD=0이면 모든 값이 동일하다는 뜻이라 이상치 감지를 건너뜀)

### 이건 표시만 하는 용도

MAD가 잡은 이상치는 지수 계산에서 제거하지 않는다.
중앙값 집계를 쓰기 때문에 아이템 하나가 이상해도 전체 지수에 큰 영향이 없다.
다만 "이 날짜에 이 아이템이 특이했다"는 정보를 사용자에게 보여주기 위해 감지한다.

## 집계 방법: 중앙값 (Median)

### 왜 평균이 아닌 중앙값인가

바스켓에 5개 아이템이 있을 때:

```
아이템별 정규화 지수: [98%, 102%, 105%, 99%, 350%]

평균 = 150.8% → "활발함!" (거짓 양성)
중앙값 = 102% → "보통" (정확)
```

하나의 아이템이 패치/이벤트로 뛰어도, 나머지 4개가 정상이면 중앙값은 흔들리지 않는다. 이것이 Hampel에서 스파이크를 다 못 잡았더라도 최종 지수에 영향이 적은 이유.

## 전체 파이프라인 흐름도

```
[바스켓 아이템 5개의 일별 거래량]
         │
    ┌────┼────┬────┬────┐
    │    │    │    │    │
   A1   A2   A3   A4   A5    ← 아이템별
    │    │    │    │    │
[Hampel] 각각 스파이크 제거    ← Phase A
    │    │    │    │    │
[STL]   각각 요일 효과 제거    ← Phase B
    │    │    │    │    │
    └────┼────┴────┴────┘
         │
    전체 중앙값 시계열
         │
    [PELT] 변화점 탐지          ← Phase D
         │
    ┌────┼────┬────┬────┐
    │    │    │    │    │
    체제별 정규화 (각 아이템)
    │    │    │    │    │
    └────┼────┴────┴────┘
         │
    일별 중앙값 = 활동지수
         │
    [MAD] 이상치 감지 (표시용)  ← Phase C
         │
    최종 차트 출력
```

## 차트 읽는 법

| 요소 | 의미 |
|---|---|
| **금색 실선** | 정제된 활동지수 |
| **회색 점선** | 정제 전 원본 지수 (비교용) |
| **100% 수평선** | 최근 30일 평균 = 기준선 |
| **빨간 수직 점선 (CP)** | PELT가 감지한 체제 전환 시점 |
| **빨간 ▼ 마커** | MAD가 감지한 이상치 날짜 |
| **배경색 교대** | 서로 다른 체제 구간 |

## 한계와 주의사항

1. **데이터 최소 요구량**: 바스켓 아이템 3개 이상, 15일 이상 거래 기록 필요
2. **자기충족 아이템 문제**: 레미의 빛나는 성수 같은 건 개인이 자급자족하는 경우가 많아, 경매장 거래량이 실제 소비량을 반영 못 할 수 있음 → 바스켓 구성 시 범용 소비재 위주로 선정
3. **신규 아이템**: 추가된 지 30일 미만이면 이동평균 기준이 불안정 → 최소 15일 필요
4. **PELT 민감도**: penalty를 낮추면 작은 변동도 체제 전환으로 잡음. 현재 5.0으로 보수적 설정
